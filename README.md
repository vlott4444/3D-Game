# Совет мудрецов

Браузерный многопользовательский 3D-зал для совместного решения задач. React, Three.js / React Three Fiber, Rapier, Colyseus, SQLite и локальная Ollama. Обновлено 1 ноября 2026 года.

## Запуск

Node.js 22.13+ и уже установленные зависимости. Новых пакетов для обновления диалога не требуется. На серверном компьютере должна работать Ollama с qwen2.5:3b; адрес и модель задаются OLLAMA_URL / OLLAMA_MODEL. Клиентам нужен браузер.

```bash
npm start
```

В другом терминале из корня проекта:

```bash
npm run dev --workspace=apps/frontend
```

Открыть http://localhost:3000. Для подключения другого ноутбука должны быть доступны порты 3000 и 2567 в локальной сети. Физический запуск на двух ноутбуках без интернета отдельно не проверялся.

## Взаимодействие

- WASD — движение, Shift — бег, пробел — прыжок, мышь — камера. Esc закрывает диалог / освобождает мышь.
- Рядом с отдельным мудрецом появляется E для разговора с ним. Рядом с круглым столом — E для обсуждения с советом.
- «Чат игроков» открывает канал людей из любой точки мира. Выпадающего списка адресатов больше нет.
- «В зал» возвращает к входу. От входа нужно подойти к столу или выбранному персонажу.
- Приблизиться к столу или NPC необходимо и по проверке сервера. Простого указания npcId в сообщении недостаточно.

Большое диалоговое окно занимает почти весь доступный экран. Основная переписка имеет собственную прокрутку, текст 17 px (16 px на узком экране). Задача, действия с посетителем, роли и состояния находятся сбоку. «О задаче» скрывает/открывает эту панель; «Развернуть» использует весь экран. На узком экране боковая информация открывается поверх чата только по запросу. Enter отправляет сообщение, Shift+Enter добавляет строку. Фокус остаётся внутри модального окна; Esc его закрывает.

## Задачи и посетители

Можно сразу обсуждать собственную задачу. У стола также можно пригласить одного посетителя с подготовленной проблемой. Он входит за пять секунд; после хотя бы одного ответа игрок решает, когда завершить приём. Посетитель уходит за пять секунд и удаляется из сцены. Автоматической проверки правильности решения нет.

Подготовлены ситуации о распределении воды, расписании генератора, противоречивых отметках времени и споре о дороге через сад. Тексты ситуаций заданы заранее, ответы генерирует LLM. Отдельный разговор с самим посетителем пока не реализован. Текущий приём живёт в памяти комнаты и сбрасывается при перезапуске сервера.

Название и активный сценарий теперь «Совет мудрецов». Старый сюжет про убийство не используется в интерфейсе или запросах к модели. Старые данные в SQLite и неактивные профили прежних персонажей не удалены. История старого детективного режима не подмешивается в новый свободный разговор.

## Характеры и обмен доводами

Эйнштейн проверяет гипотезы, Найтингейл защищает необходимые потребности людей, Ада превращает идеи в правила, Макиавелли проверяет исполнение и интересы, Сократ уточняет критерии справедливости, Диоген ищет простое достаточное действие. Профили содержат приоритеты, методы, манеру речи и ситуационные подходы. Это художественные интерпретации личностей.

Обычному общему вопросу назначаются 1–3 участника. Имена в сообщении задают состав, «пусть ответят остальные» приглашает не отвечавших в прошлом ходе. Явно можно запросить полный круг. Диспетчер работает локальным алгоритмом по теме и давности выступления, не тратя отдельный LLM-вызов. Он всегда выбирает хотя бы одного человека.

Первый участник отвечает игроку. Следующий получает короткую настоящую цитату предыдущего предложения и задачу оценить её через свои приоритеты: возразить с основанием, уточнить риск или поддержать с условием/проверкой. Прежний разговор фиксируется на начало хода, а внутри хода передаётся отдельная цитата до 600 символов. Так есть конкретный предмет реакции без растущего пересказа всех ответов. В интерфейсе показано «В ответ: …» и начало обсуждаемого довода.

Спор не навязывается ради эффекта. Допускаются осмысленное согласие и воздержание следующих участников. Первый не может воздержаться; при недоступной модели выводится ошибка. Явные текстовые повторы отбрасываются; из частичного повтора сохраняется новая часть. Семантическая уникальность и логическая правильность каждого ответа не гарантированы маленькой моделью.

В комнате идёт один ход совета одновременно. Все профили обслуживает одна локальная модель, ответы последовательно ограничены 150 токенами. Canvas продвигает кадры вручную с бюджетом 40 Гц при игре / 12 Гц при диалоге. Это не гарантированный FPS на любом устройстве.

## Хранение и история

Регистрация/вход предшествуют WebSocket; сервер проверяет JWT. Новые пароли — scrypt, старые bcrypt-хеши поддерживаются. SQLite хранит состояние игроков и память. Поза передаётся примерно раз в 200 мс, записывается до подтверждения pose_saved; при входе восстанавливается последняя подтверждённая позиция. Не подтверждённое перед аварией движение может потеряться.

В таблице dialogue сохраняется память по игроку, персонажу и случаю; в LLM попадают последние восемь сообщений. Свободные задачи имеют отдельный case_id open-council; приёмы посетителей изолированы по UUID.

Для интерфейса добавлены chat_entries и chat_receipts: один вопрос записывается один раз, а не по числу ответивших NPC. Сохраняются канал, случай, адресат реакции и список получателей комнаты. История выдаётся только получателю, отдельно для совета, каждого NPC и чата игроков. Реплики видны игрокам той же комнаты; это не приватная переписка. В интерфейс загружается до 100 последних записей канала и случая, суммарный клиентский буфер ограничен 300 сообщениями. Активный приём после перезапуска не восстанавливается, хотя его записи остаются в БД.

Старые таблицы и записи не удаляются. Миграция добавляет только новые таблицы истории. Существующие аккаунты, позиции и секрет авторизации сохраняются.

## Мир и пределы реализации

Сервер создаёт детерминированные чанки 64×64 по seed и координатам. Клиент получает окно 3×3 через авторизованный WebSocket и заменяет старые чанки новыми. Не более девяти чанков и 90 процедурных объектов активного окна. Деревья и камни используют instancedMesh. Зал и шесть мудрецов — постоянная сцена фиксированного размера.

Координаты продолжаются за прежней границей; технический предел — 10 миллионов по модулю. Для очень дальнего мира нужен floating origin. Лимит девяти чанков ещё не доказывает требование ТЗ «≤10% всех данных мира»: нужны конечный манифест, учёт ресурсов в байтах и проверка отношения cachedBytes/totalWorldBytes. WebXR, голос, голосование за доводы и коллаборативные рекомендации пока не реализованы.

## Проверки

24 автоматических теста: сохранения, JWT/пароли, авторизация WebSocket, два клиента, выбор участников, настоящая передача цитаты в запрос следующему агенту, память, каналы/получатели истории, перезапуск SQLite, расстояния до стола/NPC, посетители, чанки. TypeScript backend/frontend и production-сборки проходят. Предупреждение Vite о пакете около 3,6 МБ остаётся.

Браузерный тест с контролируемой моделью прошёл подход к столу/Диогену, E, отсутствие select, общий и отдельный каналы, карточки реакций, чат игроков, Esc и разворот окна. Проверены размеры 1440×900, 1280×720, 800×650, 390×740. Высота переписки соответственно около 585, 405, 345, 460 px; ошибок JavaScript нет.

Отдельно проверена настоящая qwen2.5:3b: Макиавелли предложил проверяемое расписание, Сократ отреагировал с обращением «Возражу, Макиавелли» и спросил, кто проверит выбранного мастера. Запросы заняли примерно 23 и 27 секунд без дополнительной 3D-сцены. Это результат конкретной проверки, не обещание скорости или качества каждого ответа.

Проверки выполнены на Windows Node.js 24 в отдельной копии проекта; установщик повторяет проверки в WSL. Прямой командный доступ к WSL в текущей сессии возвращает Wsl/E_ACCESSDENIED, поэтому изменения применяются через apply-dialogue.sh.
