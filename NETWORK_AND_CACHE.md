# Локальный сервер и подгрузка игрового мира

1. На **твоём компьютере-сервере** установи Node.js >=22.13; в корне проекта выполни `npm ci`.
2. Запусти backend: `npm start` (порт 2567).
3. В отдельном терминале запусти frontend: `npm run dev -w apps/frontend` (порт 3000, слушает 0.0.0.0).
4. Остальные игроки на той же Wi-Fi сети открывают `http://<ЛОКАЛЬНЫЙ_IP_ТВОЕГО_КОМПЬЮТЕРА>:3000`. В браузере WebSocket адрес формируется по `location.hostname:2567`.
5. Разреши входящие соединения к портам 3000 и 2567 в брандмауэре. Не публикуй их напрямую в интернете. Ollama на серверном компьютере доступна backend через `127.0.0.1:11434`.

## Ограничение 10%

Процедурный мир теперь определён как **121 чанк (11 x 11, cx/cz от -5 до 5)**. Сервер генерирует данные объектов по позиции игрока и отправляет не более девяти ближайших чанков. Дополнительно сервер вычисляет размер JSON данных объектов для всех 121 чанков и включает новый чанк только если общие байты окна не превышают 10% общего объёма. На клиенте новая полная выборка **заменяет** старую; дополнительного кеша чанков нет. Клиент проверяет `cache.cachedBytes`, `cache.worldTotalBytes`, количество чанков и отклоняет снимки свыше 10%.

**Область измерения**: сериализованные данные процедурных чанков (земля/деревья/камни), не текстуры, движок, заранее встроенная геометрия зала, история чатов и WebGL GPU-память. Для абсолютного ограничения всех данных приложения потребуется отдельный учёт этих категорий. Граница координат игроков на сервере: |x|,|z| < 320 игровых единиц. Новое сообщение `world_snapshot.cache` позволяет проверять бюджет в отладчике.

## Интерфейс

Общий совет неподвижен; чат игроков сворачивается/разворачивается; новый системный шрифт; текстовые тени сняты. Чаты и приватность переписки не изменены.
