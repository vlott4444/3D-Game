# Объединение Roma + vit + feature/frontend

Основа — чистая пользовательская ветка Roma, коммит 081fdd4, после сброса предыдущего merge. Дополнения взяты из переданных архивов vit и feature/frontend. Это проверенное объединение исходников; повторный git merge архивов не требуется.

## Применение

Останови frontend и backend через Ctrl+C, Ollama оставь работающей. В Ubuntu:

```bash
bash путь_к_пакету/apply-three-branches.sh
```

Команда сверяет изменяемые файлы, создаёт резервную копию в ~/wisdom-three-branches-XXXXXX, применяет пакет, проверяет форматирование и типы, запускает тесты и сборку. Зависимости заново не устанавливает. Локальные БД и .env не подменяются данными из архивов. Индекс Git, ветка и история не меняются, коммит не создаётся. При неизвестных правках команда останавливается до замены файлов.

После «Готово»:

```bash
cd ~/3D-Game
npm start
```

Во втором терминале:

```bash
cd ~/3D-Game
npm run dev --workspace=apps/frontend
```

Обнови вкладку браузера. Старые установщики apply-living* для этой версии не нужны.

## Что взято из каждой ветки

- Roma: шесть разных мудрецов, очередь локального ИИ и реакции на предыдущие аргументы, большой адаптивный диалог, E рядом с конкретным персонажем / столом, сохранение позиции, процедурные чанки, каталог 30 посетителей с защитой от повторов, 162 реактивных NPC в окрестности, создание и сохранение объектов мира.
- vit: панель администратора, метрики FPS/пинга, редактирование поведения агента. Перенос исправляет исходные дефекты: API проверяет JWT и роль; редактор реально влияет на запрос к LLM и сохраняет инструкцию в SQLite. FPS считается по кадрам 3D-сцены, пинг — по обмену с сервером. Метрики измеряются клиентами и служат для диагностики.
- feature/frontend: постоянный полупрозрачный чат игроков, сворачивание, уведомления входа/выхода, загрузка предыдущих сообщений, возврат управления после отправки, белые подписи с обводкой, стрелка у стола, портреты из игровых моделей и расположение HUD справа.

Компактное старое окно из frontend заменено нашим большим диалогом. Меню выбора собеседника не возвращается: подойди к нужному мудрецу и нажми E. У стола E открывает общий совет. C позволяет открыть переписку совета для чтения издалека; отправка в совет и вызов посетителя требуют подхода к столу. Из зала и мира не исчезли массовые NPC и построенные объекты.

## Чаты и память

Личный разговор виден только владельцу аккаунта. Сервер не рассылает ни запрос, ни ответ другим игрокам. Его память отделена от общего совета даже при совпадении задачи. Личная история восстанавливается для того же аккаунта и мудреца. Ответ заканчивается событием завершения и при успехе, и при ошибке модели.

Общий чат и общий совет доступны всем подключённым игрокам этого серверного процесса, в том числе в разных комнатах. Старую публичную историю из chat_entries сервер переносит в global_messages однократно, не перенося индивидуальные цели. История выдаётся страницами по 100 сообщений; клиент держит окно до 500 записей. Ссылки на предыдущие аргументы сохранены.

## Администратор

По умолчанию администратор — самый ранний зарегистрированный аккаунт в существующей локальной БД. Выбор сохраняется в server_settings; выход администратора не передаёт права случайному следующему игроку. Войди под этим аккаунтом: справа появится «Админка».

Для явного назначения другого существующего аккаунта добавь в серверный .env строку ADMIN_USERNAME=имя_аккаунта и перезапусти backend. Это серверная настройка; регистрации и пароли не сбрасываются.

В панели выбери мудреца и сохрани дополнительную инструкцию. Она действует на следующие генерации, включая личные разговоры, и переживает перезапуск сервера. «Восстановить исходное» удаляет дополнительную инструкцию, возвращая поведение JSON-профиля. Изменение не переписывает уже показанные реплики и не требует скачивать другую модель.

## Проверки и пределы

42 автоматических теста: авторизация, позиции после повторного входа, общий мир, посетители, создание объектов, приватность двух аккаунтов, общая переписка между комнатами, поздний вход, пагинация, раздельная память, права админки, применение её инструкции и сохранение настроек после перезапуска БД. Проверки типов frontend/backend и обе сборки проходят.

Проверка в браузере использует контролируемые ответы Ollama: это проверка маршрута и интерфейса, а не скорости настоящей модели на Intel GPU. Показатели FPS с тестовых скриншотов не являются замером твоего ноутбука. Гарантия ≤10% данных всего мира и WebXR этим объединением не добавляются; прежние ограничения описаны в README.
